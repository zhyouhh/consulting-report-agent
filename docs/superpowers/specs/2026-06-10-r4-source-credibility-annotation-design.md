## 1. 背景与问题

### 1.1 领导诉求
报奖 demo 后领导评审提出担心：「AI 找的资料可信度不高」，希望对资料来源的可信度有所甄别。

### 1.2 现状（实锤）
现状只校验「**有没有**来源」，不校验「**可不可信**」：

- 证据链路：S1 `references.md`（源清单）+ `notes.md`（笔记）→ **S2 `data-log.md`**（每条事实绑一个来源，格式见 `skill/SKILL.md:87-105`，每条含 `**来源**`/`**时间**`/`**URL**`/`**用途**`）→ S3 `analysis-notes.md` 引 `[DL-id]` → S4 正文。
- 放行门禁 `_has_enough_data_log_sources`（`backend/skill.py:716`）只数「带有效来源标记的条目数」达阈值即放行 S2→S3，**不看来源质量**。有效来源识别靠 `_EVIDENCE_MARKERS`（`backend/skill.py:141`）：`https?://` / `material:<id>`（子串）/ `^(访谈|调研)[:：]`（**行首**）。
- 数据基础现成：四家搜索源结果已 `urlparse` 出 domain；但 data-log 来源标记**不止 URL**，还有 `material:<id>`（用户材料）/`访谈:`/`调研:`——**一半没有域名**。

### 1.3 2026-06-09 数据论证（否掉软白名单）
worklist 原 2026-06-06 补充思路想加「软白名单 + 不在名单的确认一句」。落地前数了两份真实报告：每份仅 **3-4 个不同域名**、7 个源中 **6 个高可信**（政府/学术/官方/头部律所）。两个结论都指向**回归初版纯标注**：① 软白名单"确认一句"打断成本≈0（源就这么几个），但 ② 白名单价值也弱（绝大多数本就高可信）。软白名单"请回了当初故意否掉的维护成本"，不划算。

### 1.4 问题陈述
要给每条资料一个**可信度信号**，让用户/领导对「报告的证据底盘有多硬」有感知、在有隐患时能介入——但**不引入门禁**（领导诉求是"甄别"不是"卡死"，硬门禁会误杀好的一手源）。

## 2. 目标与非目标

### 2.1 In Scope
- **G1 内置三档参考**：产品内置一套「来源机构性质→可信度档位」规则参考（§4），随 `SKILL.md` 注入给模型；用户（含终端同事）**零维护**。
- **G2 逐条色点标注**：模型在 **data-log 每条 `**来源**` 行**标可信度色点；可信度顺 `[DL-id]` 传导到分析与正文。
- **G3 S2 阶段小结**：S2 采集告一段落时，模型读 data-log 报一句分布小结（含低质点名 + 补源建议）。
- **G4 全程 advisory**：标注与提醒都是参考，不阻断任何阶段推进。

### 2.2 Out of Scope（不做 / 后置 v2）
- **域名白名单 + 分级硬门禁**：永久维护成本 + 误杀一手源（领导设想，2026-06-09 数据否掉）。
- **软白名单"不在名单确认一句"**：同上，数据证明价值弱。
- **让用户选/维护名单**：违反"不让用户思考"；三档规则由产品内置。
- **后端按域名确定性盖章（铁准版）**：v1 纯 prompt 让模型标；确定性盖章留 v2（§9）。
- **一手 / 二手维度**：另一个正交维度，v1 不混入，留 v2。
- **HTML badge / 常驻工作区证据统计条**：v1 用色点 emoji；预览虽支持 HTML 渲染（`rehypeRaw`）但留 v2。

## 3. 关键设计决策（决策记录）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 分类维度 | **按来源机构性质，不按域名**（域名仅辅助线索） | data-log 来源含 material/访谈/调研，一半无域名；纯域名表也覆盖不全表外（2026-06-09 实测） |
| D2 | 档数 | **三档：高 / 中高 / 其他** | 符合领导"分三档"原话；"其他"兜底→覆盖率 100%，解决"表外硬猜/未分级"的尴尬 |
| D3 | 高档范围 | **政府 / 官方统计 / 国家级权威机构**（含顶级学术与国际组织） | 别把中科院院刊、世行 IMF、统计局数据压到中高；领导怕的是"用了不靠谱的源" |
| D4 | "其他"语义 | **中性兜底，≠差**；含企业官网/财报/行业协会等**可靠一手**；**非 URL 来源（material/访谈/调研）默认归此**（§4） | 防误杀：华为官网（用户亲提的高可信源）、内部访谈、用户材料既非政府也非媒体，会落"其他"——不能让用户以为差 |
| D5 | 风险提醒触发 | **挂"低质特征"（博客/营销软文/内容农场/来源不明），不挂"档位低"**；低质源可在来源行后加简短风险括注（持久落点） | 否则每份报告一半的可靠一手源（落"其他"）都被报警，反成噪音；括注让低质风险在 data-log 持久可见、不只活在 S2 小结 |
| D6 | 标注落点 | **data-log `**来源**` 行为主**；references 顺带；analysis/正文靠 `[DL-id]` 继承不重标 | data-log 是"事实←来源"逐条绑定处，标这里=每个进报告的事实都带可信度，且沿 DL-id 端到端传导 |
| D7 | 标注形态 | **色点 emoji（🟢/🟡/⚪）** | 编辑态是 textarea 裸源码（R3），emoji 可读；跨任何渲染都不坏；HTML badge 编辑态是一坨、留 v2 |
| D8 | S2 小结触发 | **prompt 可执行**：模型准备进 S3 / 写 `analysis-notes.md` 时，读 `data-log.md` 按色点计数、输出一次 advisory 小结 | v1 不改 backend，没有"阶段一次"的确定事件；触发条件必须是模型自身能判断的（"我要写分析了"=S2 告一段落），不依赖 backend 信号 |
| D9 | 实现载体 | **v1 纯 prompt（`SKILL.md`），不动 backend** | 标注/小结都是给模型的格式规则 + 内置参考，零代码改动；后端确定性统计留 v2 |

## 4. 三档定义（内置参考）

| 档 | 配色 | 含 | 判断线索（含域名辅助） |
|---|---|---|---|
| **高** | 🟢 | 政府部门、官方统计、国家级权威机构、国际权威组织 | `.gov.cn`、统计局/央行/部委、中科院社科院/国研中心、世行 IMF OECD WHO |
| **中高** | 🟡 | 有公信力的媒体与研究机构 | 新华社/人民日报/央视、财新等财经媒体、头部行业研究院/智库 |
| **其他** | ⚪ | 其余来源（**中性，≠差**）：含企业官网/财报/行业协会等**可靠一手**，也含一般网络内容 | 不属上两类的一切；模型**不为表外来源硬猜高/中高** |

### 4.1 非 URL 来源归档规则（codex R1-B1）
data-log 来源约一半不是网址，按下列默认归档，**不靠域名**：

- `material:<id>`（用户上传材料）、`访谈:`、`调研:`：**默认 ⚪ 其他**——它们多为可靠一手（内部数据、专家访谈、自建问卷），但"可靠一手"本就归"其他"（其他≠差）。
- **仅当来源主体明确是高/中高机构时上调**：如 `material` 是统计局/部委发布的文件、访谈对象是政府官员或公认权威专家 → 按其机构性质上调到 🟢/🟡。
- **风险提醒只在主体缺失/无法识别材料来源/明显营销转载博客特征时触发**——不因"没有公网 URL"就判低质。

### 4.2 风险提醒（独立于档位）
仅当检出**低质特征**——个人博客、营销软文/软广、内容农场、来源不明——才主动提醒该结论的来源风险。可在来源行后加简短风险括注作持久落点：`- **来源**：⚪ XX博客（个人博客）`；可靠一手的 ⚪ **不**加括注。

## 5. 标注落点与传导

data-log 每条在现有 `**来源**` 字段值前加色点（在已有字段上加格式）。下列示例覆盖**全部来源标记类型**（URL / `material:` / 访谈 / 调研）+ 低质括注——**注意 `访谈:`/`调研:` 必须单独行首成行**（否则后端 `^(访谈|调研)[:：]` 不计数，见 §7）：

```markdown
### [DL-2024-01] 财政部数据资源暂行规定
- **来源**：🟢 财政部
- **时间**：2024-01-01
- **URL**：https://www.mof.gov.cn/...
- **用途**：政策基石，用于第一章背景

### [DL-2024-07] 某公司年度运营数据
- **来源**：⚪ XX 公司投资者关系页（企业官网·可靠一手）
- **时间**：2024-02-10
- **URL**：https://ir.example.com/...
- **用途**：测算市场份额

### [DL-2024-09] 内部市场测算模型
- **来源**：⚪ 公司战略部测算模型（内部材料）
- **时间**：2024-02-01
- **URL**：material:mat-123
- **用途**：自下而上估算 SAM

### [DL-2024-12] 运营负责人访谈
- **来源**：⚪ 运营负责人访谈
- **时间**：2024-01-03
访谈:运营负责人-2024-01-03
- **用途**：识别执行阻力

### [DL-2024-15] 华东中小企业问卷
- **来源**：⚪ 自建用户问卷
- **时间**：2024-01-20
调研:华东中小企业-2024-01-20
- **用途**：需求侧验证

### [DL-2024-18] 个人博客（低质，带风险括注）
- **来源**：⚪ 某行业博客（个人博客）
- **时间**：2024-01-18
- **URL**：https://someblog.example.com/...
- **用途**：仅作背景参考，关键结论不单独依赖
```

- **references.md**：源清单层顺带标档（总览），非必须。
- **analysis-notes / 正文**：引用 `[DL-id]` 即继承该条可信度，**不重复标**。
- **notes.md**：S1 草记，不强制。

## 6. S2 阶段小结（codex R1-B3：prompt 可执行）

不依赖 backend 事件。触发与计数都由模型自身完成：**当模型完成一轮 data-log 写入、准备进入 S3 或开始写 `analysis-notes.md` 时**（或上下文/工具结果显示来源数已达标），先读取当前 `plan/data-log.md`，按各条 `**来源**` 行的色点计数，输出一次 advisory 小结。形态示例：

> 这一轮搜集 12 条材料：🟢 高可信 7（财政部/统计局/中科院）、🟡 中高 3（财新等）、⚪ 其他 2。其中「XX 个人博客」来源偏弱，第三章那个增长率建议再找个权威源佐证。

- **先报分布**（回应领导"可信度高不高"，给可量化的安心）+ **再对低质特征点名**（引导补源）。
- "其他"**只报数、不渲染成问题**（含可靠一手源）；只有低质特征才点名。
- 频率：进 S3 前报一次即可，**不写"精确阶段一次"**（纯 prompt 给不了 backend 级保证），不是每次 `web_search` 都报。

## 8. 验证点（codex R1-N2：最小人工验收矩阵）

advisory 行为、无硬门禁，以人工抽检为主，但必须覆盖各来源类型（风险正在类型覆盖、非 URL happy path）。最小矩阵——每类 1 条，验三列：

| 来源类型 | 期望色点 | 是否计入有效来源 | 是否误报风险 |
|---|---|---|---|
| 政府 URL（`.gov.cn`） | 🟢 | 是 | 否 |
| 权威媒体 URL（财新等） | 🟡 | 是 | 否 |
| 企业官网 / 财报 | ⚪ | 是 | **否**（可靠一手不误报） |
| `material:<id>` 用户材料 | ⚪（主体权威则上调） | 是 | 否 |
| `访谈:受访者-日期`（行首） | ⚪ | **是**（验行首计数生效） | 否 |
| `调研:对象-日期`（行首） | ⚪ | **是** | 否 |
| 个人博客 / 营销软文 | ⚪ + 风险括注 | 是 | **是**（点名提醒） |

另验：S2 小结出现、先分布后点名、"其他"措辞中性、模型确实读了 data-log 数色点；色点在编辑态（textarea 源码）可读、预览态正常渲染。（无新增后端门禁测试。）
